# 0.8 性能阶段报告

2026-09-30，比较 **0.7 build 9** 与 **0.8 build 24**。无扩展的三轮原生体验和 1 / 5 / 10 标签物理内存测量完成；本页不是完整发布验收，也不是 Chrome 对照。完整范围继续遵循 [0.8 计划](plan-0.8.md#7-发布验收)。

## 条件与版本

同一台 Mac17,4、10 核、16 GiB、macOS 27.0（26A428）。正式样本均保持温控 nominal、前台、未锁屏、非省电；开始前温控为 fair，等待恢复后才启动采样。先完整测 0.7，再完整测 0.8，没有删除较慢轮次，也没有关闭正常用户的其他应用。

原生体验使用临时源码副本加入同一探针，分别基于 `633745bf23f77088830891d4dd2ea4423648dc10` 与 `a3bf90daa0ff98e4280e05e1e01a97d4d854bbe4`，每版三轮独立空配置、10 个全部加载的自有长页面，网页视口 1280×780，显示器最高 50 Hz。这是带测量探针的 release 构建，不是分发二进制。源码、探针、启动插入代码、运行器与二进制哈希见 [公开样本](benchmarks/0.8-experience.json)。

## 原生体验

表中取每轮指标的三轮中位数；切换 P95 先从每轮 30 次切换计算。

| 指标 | 0.7 build 9 | 0.8 build 24 | 变化 |
|---|---:|---:|---:|
| 新进程启动至地址栏可输入 | 383.0 ms | 343.5 ms | −10.3% |
| 标签激活至两次 rAF，中位数 | 40.01 ms | 40.04 ms | +0.09% |
| 标签激活至两次 rAF，P95 | 180.04 ms | 140.15 ms | −22.2% |
| 四秒滚动的 rAF 间隔，P95 | 21 ms | 22 ms | +4.8% |
| 十标签空闲，整组 CPU / 单核 | 1.352% | 1.368% | +0.016 个百分点 |
| 元素捕获服务至文件落盘 | 19.24 ms | 18.15 ms | −5.7% |
| 整页捕获服务至文件落盘 | 2224.66 ms | 2238.22 ms | +0.61% |

这组中位数没有触发超过 10% 的回退调查，但不能据此称为全面提速：

- 启动三轮原值为 0.7 的 **714 / 383 / 341 ms** 与 0.8 的 **1154 / 343 / 343 ms**。0.8 首轮更慢约 441 ms；两版都存在首轮长尾，原因未定位。进程每轮新建，系统文件缓存保留，不是磁盘缓存冷启动。
- 标签与滚动指标包含 WebKit 调度，不是物理点击到屏幕呈现延迟。0.7 本批 P95 为 180 ms，上一批曾为 41 ms，批次间差异明显；不把本批下降归因于某项界面修复。
- 空闲 CPU 每轮至少采样十秒，公开 Mach 计数按时钟单位换算。0.8 与 0.7 的中位数只差约 0.0016 CPU 秒 / 十秒，主进程各轮增量也保留在报告中；不从这一微小差异推导能耗结论。
- 捕获计时只覆盖服务与落盘，不包含人工选取、结果侧栏、标注窗口或大图预览。

使用同一体验探针，单位为整组物理内存 MiB，取三轮中位数。包含归属该浏览器的 WebKit 服务，采用系统去重聚合值，不累加 RSS。

|---|---:|---:|
| 十个标签加载后 | 420.2 | 424.5 |
| 元素捕获结束 | 369.8 | 392.3 |
| 整页捕获刚结束 | 547.3 | 557.0 |

两版各轮九个已关闭 WKWebView 的弱引用均释放，保留一个标签。0.8 元素捕获后中位数多约 22.5 MiB，整页捕获十五秒后多约 7.0 MiB；这些阶段也都未超过基线 10%。这里保留的是捕获服务的最新结果，不能替代真实侧栏、标注和预览窗口的资源测量。

## 1 / 5 / 10 标签物理内存

这一组使用未加入体验探针的 release 应用，0.7 二进制 SHA256 为 `e24797ea5a0c4aefdece41417af44f062b2672b7d4f33774aaae8774d33cd174`，0.8 为 `fdc25187a3a1c44a488fb39f0eda507a352666324e00d9ee7bcf2950a68c2fbe`。每个标签数各三轮、每轮五次系统物理占用采样，两版共 90 次；采样前逐个显示所有标签，再返回第一个标签。自有测试页包含 1000 行表格、200 个 SVG 和 400 行编辑区文本，固定内部视口 1280×760。这与上一节长页面探针的负载不同，不能混合样本计算。

表中单位 MiB；括号内为各轮中位数的最小值至最大值。[公开原始数据](benchmarks/0.8-memory-stage.json)包含每次完整进程归属、物理占用、全部标签的就绪和可见状态、环境以及测量工具哈希，明确标记 `chromeIncluded: false`。

| 标签 | 0.7 build 9 | 0.8 build 24 | 中位数变化 |
|---|---:|---:|---:|
| 1 | 146.3（145.1–146.6） | 147.0（146.9–147.9） | +0.42% |
| 5 | 272.3（271.3–287.0） | 272.6（269.9–273.2） | +0.11% |
| 10 | 428.3（426.2–430.6） | 428.6（427.7–493.2） | +0.08% |

三个中位数均未触发 10% 回退阈值，但十标签最后一轮有明显波动。0.8 原值为 **427.65 / 428.61 / 493.17 MiB**，0.7 为 **430.62 / 426.15 / 428.26 MiB**；全部保留，没有丢弃样本或重跑取低值。较高轮次中，十个 WebContent 进程的物理占用之和为约 416.4 MiB，其余两轮约 351.4 / 348.8 MiB；主进程约 42.0 / 45.1 / 42.0 MiB。进程数量相同，差额主要落在网页进程，但这只是归属分析，不证明分配原因，也不能据此排除产品影响。各进程数字仅用于定位，表中的整组内存仍采用系统去重聚合值。

因此本批支持“该负载中位数接近 0.7”，不支持“所有轮次无回退”或“比 Chrome 省内存”。启动首轮长尾和这次十标签波动继续留在发布审查中。

## 复跑与剩余验收

原生体验复跑方法见 [测量工具说明](performance.md#原生体验测量探针)。本批原始记录保存在忽略目录 `qa-output/performance-08/`：体验为 `pageglass-experience-results-j2cjo7jg`（0.7）和 `pageglass-experience-results-zbkpicb6`（0.8），内存为 `benchmark-20260930-062723-23a5b7`（0.7）和 `benchmark-20260930-062948-4c850f`（0.8）。公开 JSON 只包含自有测试的测量数据，不包含浏览器配置和捕获页面。

内存比较工具改为读取实际版本，不再固定 0.6 / 0.7 标签；可单独比较两个 Pageglass 版本，省略 Chrome 时必须显式标记。新增七项测试覆盖正常聚合、可选 Chrome、回退、缺轮 / 重复轮 / 越界路径、无效原始采样、摘要不一致和运行器不一致，其中包含 18 类原始证据破坏；普通和 `python3 -O` 模式都通过，并加入 CI。未降低任何采样要求。
