# Pageglass 0.8：视觉、操作与扩展计划

2026-09-30 更新。状态：**计划已整理，版本实施中；当前为 0.8.0-alpha.1 / build 26，完整验收未完成，未发布 0.8**。本次规划核对的代码为 `dbcc9ec`。版本基线仍为 0.7.0-beta.1 build 9（产品代码 `633745b`，验证记录 `87c2fd6`）；各项验证对应的构建单独记录，不将旧构建的通过结果自动转为当前版本验收。

范围假设：“拓展功能”同时包含浏览器插件和产品经理工具。P0 为本版必须交付，P1 为本版第二批，P2 留待后续。不把兼容性试验当成已支持的功能。

## 版本目标

让 Pageglass 更像一款熟悉、清晰、顺手的浏览器：页面占主要空间，常用操作容易发现，捕获后能直接整理和交付，并能安装经过验证的 WebExtension。

保留 Swift + AppKit + 系统 WebKit、macOS 14+ / Apple Silicon 与零第三方运行时依赖。品牌只用 Pageglass；继续采用 Chrome 式两行布局，标签关闭按钮在右侧，网站图标保留。已取消的固定标签不恢复，F12 仍是真正的 WebKit 检查器。

## 交付重点与当前进度

0.8 的主线是「浏览 → 捕获 → 检查 → 标注需求 → 交给 Codex」。视觉优化首先服务于这条路径：网页占主要空间，捕获有明确文字入口，结果可检查，操作后能自然回到网页。

### 下一批执行顺序

1. **先修复明确问题（M1 / M2 / M3）：** 独立 F12 窗口命令只作用于对应检查器；定位 favicon 缓存失败；停用的内容型扩展不再允许设置不存在的工具栏动作。每项保留复现条件，修复后运行相关回归和实际界面检查。
2. **完成视觉与操作检查（M1 / M2）：** 复用现有尺寸、颜色与组件，在三种窗口宽度和明暗主题下补齐关键状态。实测更多书签的打开 / 右键编辑、输入法确认候选词、弹层关闭后的焦点，以及标注侧栏在最小窗口中的滚动。
3. **完成产品经理主路径（M2 / M4）：** 分别验证元素与已加载整页捕获；检查缺失说明，添加标注与备注，保存重开，实际粘贴或附加给接收端，再按需求运行可编辑原型。原型只复现已观察到的交互。
4. **扩展达到可日用范围（M3）：** 在已通过的两个插件功能上补齐多窗口、多个常驻动作、权限变化和真正重启；逐项公开支持与不支持范围。旧系统继续可浏览与捕获，扩展不可用原因明确。
5. **按完整门槛验收（M4）：** 完成剩余性能与系统对照，复核数据升级、资源释放及构建对应关系。通过后才进入正式发布；未验证项目保留状态，不能靠更改版本号消除。

各批次沿用下文 M0–M4 的完整范围和退出条件，不用这份优先顺序缩减原计划。声音控制仍按 [声音方案](audio-control-0.8.md) 保留范围决定与实现验收项；不以暂停视频替代静音，也不影响其他可独立工作的推进。

## 起点与上一版遗留

以下保留计划制定时的 0.7 源码基线，用于说明改进原因；不是 0.8 当前状态。已实现及实际验收结果单独记录在 [0.8 验收记录](validation-0.8.md)。

| 0.7 基线实现 | 0.8 要解决的体验问题 |
|---|---|
| [BrowserChrome.swift](../Sources/Browser/BrowserChrome.swift)：顶部约 80 pt，捕获、整页、交互记录并列为图标 | 图标含义需要猜，新增扩展后更拥挤；需要明确主次、统一状态 |
| [SettingsController.swift](../Sources/Browser/SettingsController.swift)：单页设置与统一保存按钮 | 设置增多后难以定位；更改何时生效不够直观 |
| [CapturePreview.swift](../Sources/Browser/CapturePreview.swift)、[CaptureFeedback.swift](../Sources/Browser/CaptureFeedback.swift)：每次结果新建独立面板、六项并列操作 | 捕获后焦点跳转，窗口增多，复制、检查与继续浏览的优先级不清楚 |
| [CaptureLibrary.swift](../Sources/Browser/CaptureLibrary.swift)：可搜索与清理历史，保留完整捕获包 | 缺少备注、标注和可携带的交付包；本机路径不能直接用于另一台电脑 |
| 0.7 没有 WebExtension 宿主及权限管理 | 无法安装实际插件；需要运行能力、权限与兼容性一起交付 |

0.7 尚未完成的溢出书签右键、本机 Codex 实际粘贴、Chrome 三轮多标签内存对照继续跟踪；启动与空闲 CPU 的回归调查也保留。详见 [0.7 验收记录](validation-0.7.md)及[性能报告](performance.md)。它们不阻止编写 0.8 计划和隔离开发，但不能因版本号变化而被标记完成；0.8 正式发布前必须关闭遗留阻断项并解释性能差异。

## 1. 界面统一与信息层次 · P0

### 浏览器顶部

- 第一行保持系统窗口按钮、横向标签、新建标签、标签搜索；保留标签右侧关闭和 favicon。少量标签时新建按钮紧随标签，多标签时仍在可见区域。
- 第二行按「后退 / 前进 / 刷新 → 地址栏 → 捕获 → 扩展 → 下载 / 更多」组织。捕获使用带文字的主入口：主按钮直接选元素，下拉提供捕获已加载整页、记录交互及历史；现有快捷键继续直达。
- 默认只常驻必要入口。设置、主页及不常用操作可从更多菜单进入；允许用户选择常驻工具并一键恢复默认。这里的工具显示设置不恢复固定标签功能。
- 900 pt 窗口下优先保证导航、地址输入和捕获；扩展保留一个集合入口，其余次要工具折叠。展开菜单后不挤压地址栏、不移动关闭按钮。

### 视觉规则

- 统一间距、圆角、字体和颜色，收敛为少量共享样式，逐步替换现有散落常数，不整体重写界面框架。
- 默认跟随系统，提供浅色 / 深色选择；使用系统语义色、SF Symbols 和原生控件。图标视觉尺寸约 14–16 pt，常用点击区域至少 28×28 pt；标题、正文、辅助信息分级，关键状态不靠低对比小字。
- 普通文字以 4.5:1、控件边界及状态辨识以 3:1 为设计检查目标；焦点、选中、悬停、按下、禁用必须区分。错误与记录状态同时使用文字和图形，不能只变颜色。
- 保持默认两行顶部约 80 pt 的紧凑比例，不加永久第三行装饰。动效仅用于短暂反馈，目标 120–180 ms，尊重系统减少动态效果与增强对比度设置。
- 设置、下载、历史、捕获与扩展管理统一标题、搜索、空状态、行高和主操作位置；每个面板只突出一个主操作。加载、无结果、损坏与权限不足分别说明。

**交付：** 明暗两套视觉规则，以及 900 / 1280 / 1440 pt 下的真实 AppKit 界面对照；先覆盖正常、加载、错误、选取、捕获中和部分成功六种状态，再推广到管理界面。

## 2. 高频操作与浏览连续性 · P0

- 新增 `⌘K` 本地快速操作：搜索已开标签、书签、历史和菜单命令，按类型分组，支持 ↑↓ / Enter / Esc。复用现有命令处理，不另做 AI 聊天或第二套导航逻辑；输入法组合期间不执行命令。
- 核对并补齐 `⌘+点击`、中键打开 / 关闭、关闭后恢复、标签拖动、右键菜单与键盘焦点。增加可辨认的播放声音状态和当前标签静音入口；能否控制页面声音先验证公开 API，不承诺无法实现的状态。
- 地址栏显示网站身份、加载与连接错误；编辑时保留完整地址。建议列表和所有弹层明确 Esc 返回位置，切换标签或窗口后不遗留旧建议、不抢走正在输入的内容。
- 更多书签从第一条打开，完整利用弹层宽度显示名称；↑↓ 选择并随行滚动，Enter 打开，Esc 返回网页。右键菜单必须针对被点击的书签，不能误操作之前选中的记录；键盘与鼠标分别验收。
- 设置改为「通用、外观与工具栏、浏览、捕获、扩展、数据」分组。开关与选择项即时生效，地址类输入验证后保存；失败保留输入并说明原因。清理等影响已有数据的操作继续显示范围并确认。
- 下载入口显示进行中状态；完成、取消、失败均有明确结果和下一步，打开文件与 Finder 定位保持直接。首次使用提供一次可关闭的捕获练习提示，不反复弹出引导。

声音接口核查已完成，公开 SDK 的暂停接口不能满足整页静音；本地版候选方案与现有私有接口例外的边界见 [声音控制说明](audio-control-0.8.md)。此项仍待范围决定与实现验收，不能计为已完成。

**目标路径：** 从 `⌘K` 输入到打开已有标签不超过一次选择；打开捕获历史不超过两次点击；常用操作均能只用键盘完成。录制实际操作验证路径，不用“按钮存在”作为完成依据。

## 3. 捕获检查与继续浏览 · P0

- 捕获完成后默认使用浏览器内的右侧非模态结果面板，不再每次居中新开窗口。面板约 360–400 pt，不改变被捕获网页的布局视口；下次选取前收起面板，Esc 可关闭并回到原焦点。大图和参考仍可主动独立打开。
- 顶部先给出截图、完整 / 部分结果及最重要的缺失项；主操作为「复制给 Codex」，复制截图、参考、Finder、导出放在次级区域。长图支持适合窗口、原尺寸和缩放查看，避免只展示难以辨认的小缩略图。
- 保留成功后自动复制本机引用，允许关闭自动复制；复制回执必须说明复制的是本机引用、截图还是导出文件。不能把写入剪贴板等同于 Codex 已收到图片。
- 选取模式保留父级路径和尺寸，增加一次点击返回上一级的入口；提示不遮挡目标。捕获阶段、取消与交互记录步数持续可见，失败后可重试或继续浏览。
- 关闭结果面板不删除包；清理包后同步禁用失效操作。导航失败、取消、标签关闭、多窗口切换及扩展改变页面后，选取层、任务和焦点能正确恢复。

**验收：** 连续捕获十次不产生十个窗口；捕获前后的网页视口记录一致；截图预览、取消与失败恢复不阻止下一次浏览。必须再次完成「按钮捕获 → 实际粘贴到本机 Codex → 加入新按钮 → 运行原型」，不得以本地读文件测试替代粘贴验收。

## 4. 浏览器扩展 · P0，先验证兼容范围

### 技术与系统边界

WebKit 自 macOS 15.4 提供公开的 `WKWebExtension`、`WKWebExtensionContext`、`WKWebExtensionController`，允许 WebKit 浏览器接入扩展。[WebKit 官方说明](https://webkit.org/blog/16574/webkit-features-in-safari-18-4/)、[Apple 发布说明](https://developer.apple.com/documentation/macos-release-notes/macos-15_4-release-notes)。本机 SDK 头文件也核对了这一可用版本。

采用这些系统 API，不切换 Chromium，不编写通用 Chrome API 模拟层。主程序继续支持 macOS 14；macOS 14–15.3 显示清楚的扩展不可用原因，其余浏览与捕获功能保留。最低系统版本不因扩展而悄悄提高。

### 0.8 必须可用的内容

- 扩展管理页：从本地目录或兼容 ZIP 导入，显示名称、版本、来源、请求权限、启用状态和错误；支持停用、移除及手动更新。安装采用应用持有的副本，避免移动原目录导致静默失效。
- 工具栏集合入口与可选常驻动作，支持实际 action popup、选项页及必要的标签 / 窗口事件桥接。先覆盖实际样本需要的 Manifest V3 能力，明确记录 `storage`、`runtime`、`activeTab`、内容脚本等已验证 API。
- 权限按扩展和网站管理；首次访问新范围时询问，支持拒绝与撤销。不能仅因 manifest 声明就自动授予全站访问。0.8 首版不在无痕窗口运行扩展，不向普通扩展暴露无痕标签。
- 内置页面、捕获参考、浏览器本地数据和原生捕获消息桥不授予第三方扩展。遵守现有隔离世界约束；要求页面主世界注入、原生程序通信或未实现 API 的插件明确标为不兼容，不添加私有接口绕过。
- 停用后停止后续注入与后台活动。已经修改过的网页需刷新才能完全撤销时明确提示，由用户选择刷新，不能静默丢掉未提交表单。移除时区分程序和保存的扩展数据。
- 不默认安装插件。没有启用扩展时不启动扩展后台脚本；扩展报错不阻断浏览和捕获。界面能定位出错插件、停用并重新加载。

### 兼容验证与准入

先做一个隔离技术样机，使用三个自有测试扩展覆盖弹出页 / 存储、按站点内容脚本、声明式请求规则；再选择至少两个真实开源扩展测试，例如页面样式工具和选中文字工具。选定时记录版本、源码提交、许可证、依赖 API 与具体通过路径，不预先承诺某个商业翻译或广告拦截插件兼容。

正式列为“支持扩展”前，要走通真实样本的安装 → 授权 → 使用 → 拒绝 / 撤权 → 停用 → 重启恢复 → 更新 / 卸载。声明式拦截等能力按验证结果列入兼容表；只加载 manifest 或展示图标不算通过。样机不通过时回到扩展方案评审，不用空壳管理页宣称已交付。当前逐功能结果见 [真实扩展兼容记录](extension-compatibility-0.8.md)，保留失败和未覆盖路径。

Chrome Web Store 直接安装、任意 CRX 兼容、扩展商店和后台自动更新属于 P2。翻译插件若向服务端发送内容，要显示该插件的权限与数据去向；Pageglass 不额外加入默认云端服务。

## 5. 产品经理工具 · P1，本版第二批

| 功能 | 用户操作与范围 | 验收重点 |
|---|---|---|
| 截图标注 | 在结果中添加矩形、箭头、序号和文字，支持撤销 / 重做；可写本次修改要求 | 原始截图与参考代码不变，标注另存；重新打开仍可编辑，导出图片与标注数据一致 |
| 捕获整理 | 修改显示名称、添加备注、按元素 / 整页与日期筛选；搜索包含用户备注 | 元数据独立保存，旧包可读，不重写原页面证据；200 条记录下操作与搜索顺畅 |
| 可携带捕获包 | 导出包含截图、参考、结构、资源、交互记录和用户标注的 ZIP / 文件夹 | 内部引用相对化；移到另一目录后仍能读取和预览；不带浏览器配置、Cookie 或机器绝对路径 |

默认本机快速复制保留。可携带包由用户自行附加给接收工具，不声称导出后已自动上传或已适配所有云端 Codex；在实际目标工具完成一次导入 / 附加与重建验收，资源缺失仍显示。

双网页分屏、截图差异对比、项目工作区、团队同步和内置 AI 服务放到 P2，避免 0.8 同时引入多套页面生命周期及云端依赖。

## 6. 实施顺序

| 阶段 | 工作与交付 | 退出条件 |
|---|---|---|
| M0：范围与技术确认 | 当前界面问题清单、视觉规则、关键状态稿、扩展 API 样机和候选插件表；继续关闭 0.7 遗留项 | 扩展宿主与权限路径实际可行，系统版本和兼容边界明确 |
| M1：浏览器界面 | 顶部布局、统一控件状态、主题、工具显隐、设置分组 | 明暗 / 窄窗口 / 30 标签均可操作；旧快捷键、焦点与输入法不回退 |
| M2：操作与捕获 | 快速操作、浏览细节、结果侧面板、选取与取消恢复 | 连续捕获无窗口堆积；真实 Codex 粘贴链路通过，形成 alpha |
| M3：可安装扩展 | 管理页、动作入口、权限、生命周期与真实插件兼容表 | 两个真实样本完成全流程，旧系统降级与无痕隔离通过，形成 beta |
| M4：整理与交付 | 标注、备注筛选、可携带包；性能和数据兼容回归 | 原始数据保留、可携带包实际可读、完整验收报告与构建版本对应 |

先在现有组件上迭代。共享样式、命令入口、捕获详情、标注和扩展宿主各自集中职责，避免把更多状态堆入 `BrowserWindow`。扩展生命周期与普通 / 无痕窗口的关系在样机阶段确定。捕获包采用兼容的附加元数据，不破坏 0.6 / 0.7 文件结构。

## 7. 发布验收

- **视觉：** 900 / 1280 / 1440 pt × 1 / 10 / 30 标签，覆盖明暗、增强对比度、长标题、弹层与 F12 停靠。真实截图检查密度、间距、焦点和主要操作可达性；不能只验高保真稿。
- **操作：** 鼠标、触控板、纯键盘、中文组合输入；VoiceOver 能读出关键按钮名称与状态，弹层关闭后焦点返回合理位置。右键栏内和溢出书签均实际验证。
- **捕获与交付：** 单按钮、长页、图片缺失、交互记录、取消、失败导航；标注重开可编辑，导出包移位可用，原始证据未修改；本机复制与可携带包分别验收。
- **扩展：** 拒绝授权、撤权、站点变化、无痕、坏包、更新失败与卸载；扩展停用后无残留后台活动，普通网页不能调用捕获原生桥。恶意压缩路径与越界文件必须拒绝。
- **性能：** 以 0.7 build 9 为基线，同设备至少三轮；分别测无扩展、启用两个已验证扩展、捕获 / 标注 / 预览使用后。记录启动、空闲 CPU、切换、1 / 5 / 10 标签整组物理内存和资源释放。超过 10% 的持续退步必须修复或在发布决定中解释；不把插件耗时隐去，也不以单项跑分宣称 Chrome 级体验。
- **兼容与数据：** macOS 14 的基础路径和 macOS 15.4+ 扩展路径分别验证；缺少对应系统实测就保留未验收。先对隔离副本验证书签、历史、设置、会话、捕获和新元数据迁移，不原地试验真实数据。
- **测试工具：** QA 包在缺少隔离参数时拒绝读取正常用户配置；自动化退出后不触发无参数重开。测试结束不遗留合成剪贴板，除非明确准备给用户验收。
- **构建与发布：** 运行相关单元测试、arm64 release 构建与真实 WebKit smoke，再做 UI / 扩展实测。源码、版本、安装包与报告一一对应；无 Developer ID / 公证时明确为未公证预览包。0.7 的未验收项不会被此次计划自动豁免。

每阶段提交后更新已有的 `validation-0.8.md`，记录已实现、实际通过、未完成与证据。本文是范围和验收约定，功能完成情况以 [0.8 实施与验收](validation-0.8.md) 为准。
