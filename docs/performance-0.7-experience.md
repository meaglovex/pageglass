# 0.7 原生体验测量

2026-09-29，**测量已完成，性能发布验收仍未完成**。本报告不代表 Chrome 对照，也不把页面 rAF 间隔当作屏幕呈现延迟。

## 条件与原始记录

同一台 Mac17,4，10 核、16 GiB、macOS 27.0（26A428），显示器报告最高 50 Hz。两版均为 arm64 release，使用同一探针与自有长页面；每轮独立空配置、10 个全部加载标签，保持前台、未锁屏、非省电、温控 nominal。0.6 基于 `b21b6fd`，0.7 基于 `9e00de0`；探针只加入临时源码副本，不进入分发应用。

[公开原始样本](benchmarks/0.7-experience.json)包含三个轮次的完整切换与滚动时间序列、按进程名汇总的 CPU 增量、物理内存、版本及源码/探针/运行器/二进制哈希。未附浏览器配置、捕获内容或用户数据。复跑方法和各指标口径见 [performance.md](performance.md#原生体验测量探针)。

## 三轮结果

表中为各轮结果的中位数；标签 P95 先在每轮 30 次切换中计算，再取三轮中位数。

| 指标 | 0.6 | 0.7 | 变化 |
|---|---:|---:|---:|
| 新进程启动至地址栏可输入 | 296.2 ms | 345.0 ms | +16.5% |
| 标签切换代理指标，中位数 | 40.04 ms | 40.02 ms | −0.04% |
| 标签切换代理指标，P95 | 80.06 ms | 120.13 ms | +50.0% |
| 四秒滚动的 rAF 调度间隔，P95 | 21 ms | 22 ms | +4.8% |
| 十个标签空闲，整组 CPU / 单核 | 1.11% | 1.46% | +0.35 个百分点 |
| 元素捕获服务至文件落盘 | 15.51 ms | 17.39 ms | +12.1% |
| 整页捕获服务至文件落盘 | 2220.67 ms | 2224.54 ms | +0.17% |

启动每次创建新进程，但未清除系统文件缓存；不是磁盘缓存冷启动。标签指标从原生激活调用到页面第二次 rAF 回调，包含 WebKit 往返和调度；不是物理点击到画面呈现的实测。捕获计时不包含人工选择及结果浮层展示。

## 回归调查

启动、标签 P95、空闲 CPU 和元素捕获触发计划中的 10% 调查阈值，不能称为全面提速。

- 启动绝对差约 49 ms。0.6 单轮范围 294–371 ms，0.7 为 311–350 ms，范围重叠。此前两批相同探针的中位数变化分别约 −1.9% 和 +13.4%；运行顺序和系统调度仍会影响短时间测量，目前未定位稳定的启动瓶颈。
- 标签长尾集中在空闲后第一次遍历后台标签，后续两次遍历大多约 40 ms。此前正序批次 P95 为 80→140 ms，反序复测为 80→73 ms，本次为 80→120 ms。存在明显批次波动；没有据此宣称问题已修复，也没有为跑分更改 WebKit 后台调度。
- 本次 CPU 使用公开的 Mach 时间计数并按设备时钟换算，已用独立 `getrusage` 校验。0.6 主进程十秒消耗约 0.007–0.009 CPU 秒，0.7 约 0.008 秒；增加主要出现在 WebContent 和 GPU。整组差约 0.035 CPU 秒/十秒，原因未证实，不能把主程序 UI 代码或系统 WebKit 单独认定为根因。此前 `ps TIME` 的低精度 CPU 样本只保留作排查，不混入本报告。
- 元素捕获增加约 1.88 ms，整页增加约 3.87 ms。0.7 已增加可取消、临时目录提交与结构化结果处理；这些是合理的待核查成本来源，但当前采样没有分阶段证明各自耗时，不能写成已定位。

当前保留 beta 状态。Speedometer 三款三轮已完成，见 [性能报告](performance.md)；仍须结合完整内存对照及交互验收作发布决定，这四项不在本报告中自动豁免。若继续发行预览版，须保留上述回归数值和代理指标限制，不宣传 Chrome 级速度。
