# Pageglass 0.8 build 31 资源实测

2026-10-09，在 Apple M5（10 核、16 GiB）和 macOS 27.0.1（26A434）上测量。结论：固定页面下，单标签整组内存约 147 MiB，十标签中位数约 485 MiB，空闲 CPU 约占单核 1.40%。多标签内存有明显波动；捕获后能回落，但本测试不能证明长期无泄漏、真实网站低占用或比 Chrome 更省。

## 安装版多标签内存

被测为 /Applications/Pageglass.app，0.8.0-alpha.1（31），可执行文件 SHA-256 为 `d9bf2353eeddb9a6e75e6775fced1d080b0084e7bc75e473841ad4243d7d4de0`。与工作区 release 包逐字节一致。使用独立测试配置，无扩展，不读取日常标签、历史或登录。

每个标签包含 1000 行表格、200 个 SVG 图元和 400 行编辑文本；固定内容视口 1280×760，每个标签均加载且实际显示过。每个标签数三轮，每轮五个完整样本，共 45 次。内存采用 macOS footprint 的整组物理占用，包含明确归属该实例的 WebKit 网页、GPU、网络等服务，不累加 RSS。1 MiB = 1,048,576 字节。

| 标签数 | 三轮中位数 MiB | 轮次范围 MiB | 每轮中位数 MiB |
|---|---:|---:|---|
| 1 | 147.4 | 146.7–147.9 | 147.9 / 147.4 / 146.7 |
| 5 | 276.4 | 265.5–332.3 | 276.4 / 265.5 / 332.3 |
| 10 | 485.3 | 427.8–559.3 | 427.8 / 559.3 / 485.3 |

原批次第三轮 10 标签因应用失去前台而失效；最后环境记录为温控正常、未锁屏、非省电，但前台 PID 与测试 PID 不同。保留前八个完整轮次，包括 559.3 MiB 的较高读数；只补测该失效轮次。补测调用原运行器 `run_one`，未修改负载、五样本要求或前台/温控校验。原批次没有生成完成 summary；本表明确由八个完整轮次与一个有效补测汇总。

## 空闲 CPU、捕获与释放

使用提交 `c901fff381414f2abc3c7cdbd208b0395cd3d251` 的临时 release 源码副本加入现有 ExperienceProbe，正常安装包没有修改。三轮全部完成并被运行器接受。这里使用另一种自有长页面，不能与上表混合计算。

- 10 个长页面稳定后，每轮至少采样 10 秒，整组 CPU 为单核的 **1.398% / 1.400% / 1.491%**，中位数 **1.400%**。100% 表示占满一个核心；不据此推断瓦数或续航。
- 新进程启动至地址栏可输入为 **1237 / 364 / 313 ms**。保留首轮长尾；未清空系统文件缓存，不称为冷启动。
- 元素捕获服务至核心文件落盘中位数 **23.8 ms**，整页捕获 **2227.7 ms**；不含人工选区及结果侧栏显示。

## Chrome 追加测量：仅一轮有效

2026-10-09 随后启动 Chrome 154.0.8037.98，以独立测试配置运行同一固定页面。硬件、系统、1280×760 内容视口、运行器、物理内存归属工具及负载哈希与上文一致。

只完成一轮单标签：五个完整物理内存样本为 **622.6 / 621.1 / 620.1 / 618.6 / 582.2 MiB**，中位数 **620.1 MiB**。Pageglass 单标签三轮中位数为 **147.4 MiB**。样本数量不同，仅可作初步观察，不能称为稳定节省比例。

接着的五标签测试因测试浏览器失去前台而失效。Chrome 插件连接连续失败，虽确认扩展已启用且连接组件正常，仍未取得可用的测试窗口控制；没有绕过前台、完整加载和逐标签显示校验，也未读取或修改正常 Chrome 标签。尚缺 Chrome 三轮完整的 1 / 5 / 10 标签数据和 CPU 数据。

[Chrome 阶段原始样本](benchmarks/chrome-resources-20261009-partial.json)明确标记 incomplete；本地原始记录位于 `qa-output/resources-20261009-chrome/`。测试进程由原运行器结束，日常 Chrome 保留。
