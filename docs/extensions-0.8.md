# 0.8 扩展开发预览

状态：宿主已接入，自有测试扩展通过；Shorts Blocker 的首页导航隐藏、Wide GitHub 的公开仓库主页扩宽均走通安装到卸载。GHUX 的布局失败及脚本错误仍未关闭，详见 [真实扩展兼容记录](extension-compatibility-0.8.md)。仅覆盖记录中的功能与环境，不是插件全部行为或 Chrome 扩展商店兼容承诺。0.8 版本计划见 [plan-0.8.md](plan-0.8.md)，实际验证见 [validation-0.8.md](validation-0.8.md)。

## 使用路径

1. 普通窗口工具栏的拼图按钮 →「管理扩展」，或「设置 → 扩展」。系统需 macOS 15.4+；旧系统保留浏览与捕获，并显示扩展不可用原因。
2. 导入含根目录 `manifest.json` 的目录或 ZIP，先检查名称、版本、权限和网站范围，再确认安装。不直接安装 CRX，不预装第三方扩展，不自动授予全站权限。
3. 打开一个普通 HTTP / HTTPS 网页，从拼图菜单运行已声明的扩展动作；只有内容脚本的扩展显示「网站权限…」，授权后在匹配网站自动运行。授权按协议与主机保存，匹配该主机的所有端口；新的网站范围需要另行授权。
4. 管理页可打开真实 action 弹窗、扩展设置页，停用、更新或移除程序，查看并撤销站点权限。撤权或停用停止后续注入；已经改变的页面需用户点击「刷新当前网页」才能恢复，不自动刷新未提交表单。
5. 管理页可勾选「显示在工具栏」，直接使用扩展图标打开动作；没有图标时用拼图回退。900 pt 窗口最多显示一个、1040 pt 两个、1100 pt 及以上三个，其余始终可从集合菜单运行；小于 900 pt 全部收入集合菜单。操作标题、禁用状态和提示中的徽标文字随扩展更新；无痕不显示这些动作。
6. 手动更新保留扩展身份、数据、工具栏选择和原有网站授权；安装新版本失败时尝试恢复旧版本，恢复失败单独报告。移除时程序副本进入废纸篓，默认保留扩展数据；可显式勾选同时删除数据。保留数据的条目可通过「更新」重新安装。

内置主页或本地文件作为活动页面时，该窗口会从扩展的标签查询中隐藏；回到普通网页后恢复。WebKit 要求窗口的标签列表包含活动标签，所以不以伪造当前标签的方式绕过这一约束。无痕窗口始终不接入扩展控制器。依据：[WebKit 窗口标签验证实现](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/Extensions/Cocoa/WebExtensionWindowCocoa.mm)。

## 首批范围

| 能力 | 范围 |
|---|---|
| 安装 | Manifest V3，本地目录 / ZIP；应用保存独立副本 |
| 已覆盖的运行链路 | action 弹窗、选项页、storage.local、runtime 消息、MV3 worker、静态隔离世界内容脚本 |
| 标签 | 普通网页的查询、创建、激活、关闭，以及创建 / 关闭 / 激活 / 移动 / 属性变化事件；不是全部 tabs / windows API 兼容声明 |
| API 权限准入 | storage、tabs、activeTab、alarms；允许导入不等于每一个 API 都已验收，当前不增加可选 API 权限的运行时授权 |
| 网站访问 | 显式逐站允许、拒绝、撤销；不授权 file / 浏览器内置来源或无痕数据 |
| 暂不支持 | MV2、Chrome Web Store / CRX、后台自动更新、DNR 请求规则、程序化 / MAIN world 脚本注入、原生程序通信、侧栏和浏览器内部页面覆盖 |

请求规则样机存在撤权后仍拦截的失败，保留原始结果并拒绝相关权限，详见 [样机报告](validation-data/0.8-extension-probe.json)。不使用私有接口改变扩展权限；原有检查器例外仍仅在 `DeveloperTools.swift`。

## 包和数据边界

- ZIP 使用系统 zlib 解码 stored / deflate；压缩包最多 32 MiB，单文件最多 8 MiB，解包合计最多 64 MiB，最多 2000 个文件或目录。不支持分卷、ZIP64 和加密包。
- 拒绝目录穿越、符号链接、特殊文件、大小写重名、重叠数据、解压大小不符和 CRC 错误。读取目录中的每个路径组件时拒绝跟随符号链接；失败只清理本次创建的暂存目录。
- 版本按 [Manifest 数字版本格式](https://developer.chrome.com/docs/extensions/reference/manifest/version) 校验；资源引用必须在包内且实际可读。恢复时重新校验管理副本摘要，发生变化要求手动重新导入。
- 扩展登记和程序副本位于浏览器资料目录的 `Extensions/`；持久扩展数据由 WebKit 根据固定的控制器 / 扩展标识管理。扩展记录损坏时保留原文件并停止修改，不以空列表覆盖。
- action 和选项页使用扩展自己的 WebView 配置；页面内容脚本、弹窗、选项页均不能访问 Pageglass 的原生捕获桥。已授权扩展可以修改获准网站的 DOM，不能因此承诺未知插件不会影响页面或捕获效果。
