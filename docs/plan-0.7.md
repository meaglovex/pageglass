# Pageglass 0.7 产品体验优化计划

状态：实施中，当前为 0.7.0-beta.1。基于 0.6.0（`b21b6fd`）制定，2026-09-29。实现和验收证据见 [validation-0.7.md](validation-0.7.md)；以下范围与发布门槛保持不变。

## 版本目标

让 Pageglass 能顺畅地完成「浏览 → 选取 → 检查捕获 → 交给 Codex → 再次使用」。保留当前两行浏览器布局和轻量原生实现，优先处理高频操作、异常反馈和捕获结果的可见性。

0.7 的核心交付是：**浏览不容易卡在操作上，捕获结果看得懂、找得到、能重新复制。** 性能通过同负载测量验收，不能用小安装包代替省内存的结论。

## 当前基础与实际缺口

已有标签、地址建议、书签编辑与网站图标、历史、下载、无痕、会话恢复、捕获清理，以及真正的 WebKit F12 检查器；这些是回归范围，不重新开发。

| 现状依据 | 体验缺口 |
|---|---|
| [BrowserChrome.swift](../Sources/Browser/BrowserChrome.swift)：标签最窄 110 pt、横向滚动；书签固定取前 8 个；标题更新会重建整条标签栏 | 标签多、窗口窄时的可发现性与稳定性不足，书签利用不了实际可用宽度 |
| [AddressSuggestions.swift](../Sources/Browser/AddressSuggestions.swift)：标题和地址拼在同一行 | 扫读困难，键盘选中状态不够明确，需要补中文输入法组合输入验收 |
| [WebDelegates.swift](../Sources/Browser/WebDelegates.swift) / `BrowserNotice`：加载失败、页面进程退出依靠约 8 秒的临时提示 | 用户错过提示后难以知道原因和恢复方法 |
| [CaptureService.swift](../Sources/Browser/CaptureService.swift)：完成即复制，以临时文字回执；部分结果通过警告文字判断 | 看不到截图、缺失资源与截断范围；捕获进行中没有明确的取消入口 |
| 每个窗口只保留内存中的 `latest`，历史包依靠 Finder 查找 | 重启后无法在应用里查找和重新复制某次捕获，清理缺少逐项操作 |
| [performance.md](performance.md)：已有对照工具，正式 Chrome 对照尚未完成 | Chrome 级速度、较低总内存仍没有验收结论 |

以上是源码与历史记录形成的计划依据，不代表本次完成了新的实机体验测试。

## 1. 浏览器操作打磨 · P0

### 标签、地址栏、书签栏

- 保持「标签栏 + 导航地址栏」布局，保留右侧关闭按钮、网站图标；统一明暗主题的选中、悬停、按下和键盘焦点状态。
- 新建、切换、恢复标签时，活动标签自动进入可见区域。溢出时保留可见的新建入口，并提供标签列表，能按标题或域名定位。
- 标题或图标更新只更新对应标签，避免重建标签栏造成滚动位置、焦点或拖动状态丢失。
- 地址建议分开显示标题与网址，标出书签/历史来源；完整支持 ↑↓、Enter、Esc。中文输入法确认候选词不得误触导航；切换标签不能留下旧建议面板。
- 书签栏按实际宽度排列，放不下的进入溢出菜单；右键编辑和打开行为在栏内、溢出菜单、管理窗口保持一致。
- 普通窗口的设置入口使用齿轮，避免头像图标让人误认为已有账号系统；窄窗口时次要操作进入更多菜单，地址栏仍可编辑。

### 错误与恢复

- 首次导航失败显示持续可见的错误状态，提供重试、编辑地址。旧页面仍可用时保留页面，并用明确的错误条说明本次导航失败。
- 页面进程退出提供重新加载入口；只影响故障标签。后台标签出错时保留状态，切回后仍可看到。
- 普通通知可以消失；需要用户处理的错误和进行中的任务不能只靠倒计时提示。
- 保持系统 TLS 校验，证书错误不提供跳过校验的捷径。

**验收：** 在 900 / 1280 / 1440 pt 窗口宽度、1 / 10 / 30 个标签下，活动标签、新建和关闭入口可达；20 个书签都能打开和编辑。中英文输入、长标题、连续切换、断网、无效域名和页面进程退出都有可重复操作结果。F12、Console、查找、缩放、无痕不回退。

## 2. 捕获过程与结果预览 · P0

### 捕获前和捕获中

- 进入选取模式后持续显示简短提示、当前元素类型与尺寸，显示可选父级路径；保留 ↑↓、Enter、Esc 操作，不触发原网页点击。
- 明确区分「元素可见区域」与「当前已加载整页」；记录交互时显示已记录步数和停止入口，达到上限后给出停止原因。
- 捕获显示真实阶段：生成截图、收集资源、保存结果；整页显示已处理屏数，不编造百分比。
- 增加取消按钮。取消后恢复页面滚动、临时样式和浏览操作；已经发出的系统截图回调即使晚到，也不能保存成成功结果或覆盖剪贴板。

### 捕获完成

- 继续自动复制给本机 Codex，保持现有快捷路径；同时打开轻量结果浮层，显示缩略图、范围、来源、交互步数、资源缺失和截断说明。
- 浮层提供「重新复制给 Codex」「复制截图」「查看参考」「在 Finder 中显示」。可展开查看截图，用户不必打开 JSON 才知道漏了什么。
- 使用结构化结果区分成功、部分成功、失败、已取消；不能靠中文警告关键词判断结果是否完整。
- 明确“已复制本机文件引用”。图片复制保留独立入口；不把文件路径文本描述成已经附上图片。
- 查看参考仍禁止执行原网页脚本。图片与字体加载失败、跨域受限或整页截断必须可见，不承诺未知交互已经还原。

**验收：** 自有测试页覆盖单按钮、带图片卡片、整页、展开前后状态、缺失资源、超预算、写入失败及各阶段取消。成功结果三份核心文件能读取，部分成功能看出缺失原因；取消不留下可用历史记录、不替换原剪贴板、不锁住页面。以一份按钮捕获走完本机 Codex 读取截图和代码、增加按钮并运行原型的链路；若接收端无法自动操作，保留用户实际粘贴验收项，不以剪贴板写入成功代替。

## 3. 捕获历史与清理 · P1，纳入 0.7

- 在「捕获」菜单提供「捕获历史」；完成浮层也能进入。采用列表与详情预览，不另做新标签页工作台。
- 列表显示缩略图、标题/域名、时间、元素/整页、大小和到期状态；支持搜索、重新复制、Finder 定位、逐项或批量移入废纸篓。
- 延续现有永不过期 / 1 / 7 / 30 天设置。展示占用空间和将清理的范围，手动批量清理前确认。
- 打开历史时按需读取，缩略图延迟加载，避免启动扫描全部图片。文件被外部删除或到期清理后，列表同步失效状态，不复制坏路径。
- 兼容 0.6 捕获包，不重写旧内容；损坏记录不妨碍打开其他包。遵守现有路径与符号链接限制，清理只影响选定包及确属它的剪贴板。
- 无痕窗口仍可由用户主动保存捕获，但捕获结果明确显示为已保存到本机；浏览历史与会话仍保持无痕隔离。

**验收：** 重启后可找回旧包并复制；用 200 份合成捕获包检验列表、搜索和缩略图，不阻塞浏览。逐项删除、到期边界、损坏包、目录丢失、废纸篓失败、旧包兼容和其他应用剪贴板均有检查。

## 4. 速度、资源与日常兼容性 · P0 发布门槛

- 使用现有脚本建立 0.6、0.7 和 Chrome 的对照。同一设备、相同视口及负载，至少三轮；记录系统和浏览器版本、原始样本、中位数与波动。
- 测量冷启动至可输入、标签切换、长页面滚动、空闲 CPU，以及 1 / 5 / 10 个**全部加载**标签的总物理内存。包含 WebKit 渲染、GPU、网络进程。
- 复跑 Speedometer；测量一次元素捕获和整页捕获的耗时及结束后资源释放。页面负载分数、浏览器壳响应与捕获耗时分别报告。
- 先定位最明显的瓶颈，再局部优化：优先检查标签栏重复重建、历史预览解码、已关闭标签/检查器、取消后的残留任务。没有证据不做大重构，不新增会丢失表单状态的自动休眠策略。
- 用独立测试数据补齐上传、慢速下载取消、保存、打印、标签拖动、会话恢复、F12 停靠及多窗口切换。网站矩阵至少覆盖文档、设计工具、管理后台和视频各一类；记录具体站点版本/日期、关键操作与失败表现。

**验收：** 性能报告必须有原始数据与复跑方式。0.7 对 0.6 若出现中位数超过 10% 的退步，先复测排除噪声，持续退步必须修复或在发布决策中解释；这只是回归调查阈值，不是 Chrome 性能达标线。对 Chrome 的差距如实列出，单项跑分通过不能宣称全面同级。关键浏览操作和捕获链路无阻断问题，进程/任务释放检查通过。

## 实施顺序与交付

| 阶段 | 工作 | 交付与退出条件 |
|---|---|---|
| M1：浏览器顺手 | 建立 0.6 基线；标签/地址建议/书签溢出；持久错误反馈 | 可安装 alpha；浏览器操作矩阵通过，保留基线数据 |
| M2：捕获可检查 | 选区反馈、任务状态与取消、完成预览 | 捕获关键路径与失败/取消用例通过 |
| M3：结果可复用 | 捕获历史、逐项清理、旧包兼容 | 可安装 beta；从捕获到 Codex 修改原型的整条链路完成验收 |
| M4：稳定发布 | 性能定位与优化、兼容性复测、文档与分发检查 | 0.7 验证报告、已知问题、arm64 应用及源码版本对应 |

按阶段提交和验收，不把所有变更压进一次大改。保持 Swift + AppKit + WKWebView 与零第三方运行时依赖；浏览器壳、捕获任务状态、结果预览、历史目录各自收敛职责，复用现有存储与清理逻辑。

开发完成时运行 `swift test`、`scripts/build.sh`、`scripts/smoke.sh`，并检查实际安装包的 UI。对 0.6 用户数据先做隔离副本升级验证：书签、设置、会话和旧捕获不能丢失。测试数据和真实用户数据分开；公开报告只使用可公开的样本。

## 本版范围边界

- 不恢复固定标签功能；品牌统一 Pageglass。
- “工作台”需求继续对应 F12 开发者工具，保持真实 WebKit 面板，不做另一套仿制控制台。
- 不引入双内核、扩展商店、账号同步、密码管理器或内置 AI 聊天；云端捕获同步、远程 Codex 一键上传与跨设备交付留待后续版本。
- 不承诺自动还原未知业务逻辑或任意网站 1:1。0.7 优先让已有捕获的结果、缺失与限制能被用户检查。
- 正式 Developer ID 签名、公证需要对应开发者身份；具备条件后单独接入。不具备条件时明确发布预览包，不能标为已公证。自动更新不作为本版必做项。

发布前将验证文档整理为「当前版本结论 + 历史记录」，消除旧条目与当前状态混淆；没有完成的验收保留为未验证，不由计划文档推定通过。
