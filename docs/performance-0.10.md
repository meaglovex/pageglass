# 0.10 性能优化审查与实测

2026-10-09，本期减少地址建议、标签外观同步、扩展状态匹配和 PNG 编码中的重复工作。可确认的是这些具体路径的成本下降；标签切换和滚动的整机代理指标基本不变，不能宣称整体网页加载、视频或续航都已提升。

## 代码审查与改动

| 位置 | 原有成本 | 本次处理 |
|---|---|---|
| BrowserStore.suggestions | 最多显示 8 条，却扫描并分配全部匹配记录 | 保持书签优先、历史随后、URL 去重和原语言匹配规则，收集 8 条后停止 |
| TabButton.update | 所有标签反复设置未变文字、图标、可访问名称及重绘标志 | 仅提交变化字段，共享默认图标；不改变标签的网页状态 |
| ExtensionEvents.sync | 每个标签在线性旧数组中再查找，形成平方级匹配 | 按对象身份建立一次索引，保持事件顺序和可见范围 |
| CaptureService / InteractionRecording | PNG 前先转 TIFF，再解码成另一份位图；压缩占用主线程 | CGImage 直接编码，后台压缩，保留透明度、像素、Retina DPI 与取消语义 |

手工验收还修复了旧问题：本地书签建议经通用地址解析后被拒绝。点击/回车选择现在走仍存在的书签/历史记录校验路径；直接输入 file URL、javascript 或其他原本禁用协议的规则没有放宽。

## 条件与版本

- Apple M5（Mac17,4）、10 核、16 GiB、macOS 27.0.1（26A434）。有效轮次均温控正常、未锁屏、非省电。
- 基线为 0.9 build 33，提交 c9834ac；性能候选为 0.10 build 34，提交 743994f。
- 整机采用相同临时测量探针、相同自有长页面、十个全部加载标签；各六轮。先基线三轮再候选三轮，再反向候选三轮、基线三轮。全部有效样本合并保留。
- 最终交付为 **0.10.0-alpha.1 build 35**（源码 8414b31），只在已测性能代码之后追加本地书签建议导航修复。六个性能相关源文件和标签激活方法均与已测提交逐字节相同；未把最终包说成这十二轮使用的同一个二进制。最终包另通过完整回归及实际界面检查。

## 局部代码路径

[源码微基准原始数据](benchmarks/0.10-hotpaths.json)使用 release 优化编译、同一固定数据、交替顺序各三轮。编译实际 BrowserStore、TabButton 和图形编码代码；仅为未参与工作的 BrowserTab 字段及 QAProfile 提供固定支架。旧 PNG 表达式与基线 CaptureService 校验一致。它不是完整浏览器、物理输入延迟或网页帧率测试。

| 场景 | 0.9 | 0.10 |
|---|---:|---:|
| 10,020 条记录，前部命中 8 条 / ms 每次 | 7.702 | 0.006 |
| 10,020 条记录，末部稀疏命中 / ms 每次 | 13.477 | 13.328 |
| 10,020 条记录，无匹配 / ms 每次 | 13.211 | 13.073 |
| 100 个标签的控件状态同步 / ms 每次 | 3.267 | 0.028 |
| 1440×12000 PNG 编码 / ms | 98.86 | 79.42 |
| 编码期间主执行队列任务得到运行的延迟 / ms | 98.84 | 0.32 |
| 单次编码测试进程峰值 RSS / MiB | 363.4 | 163.1 |

稀疏和无匹配查询仍须扫描全部数据，基本没有变化。PNG 的已解码像素哈希、物理尺寸与逻辑尺寸在两版一致。RSS 是独立编码进程的最高驻留内存，**不等于浏览器整组物理占用**；在验证解码另分配位图之前取值，每个新进程只编码一次，避免累计旧的临时对象夸大峰值。

初版优化丢失 DPI 的问题被测试复现：Retina 图像的原生显示尺寸会翻倍。现已补回 DPI，像素和 100% 预览比例均验证。早期三次连续编码及未补 DPI 的微基准记录保留作排查，不混入上述最终表。

## 同负载整机代理指标

[六轮对照数据](benchmarks/0.10-experience.json)包含每轮全部原始数值和工具、页面、源码、二进制哈希。rAF 是页面动画回调，反映调度节奏，不是物理输入到显示器出帧的延迟。启动保持系统文件缓存，不称为冷启动。

| 指标 | 0.9 六轮中位数 | 0.10 六轮中位数 | 变化 |
|---|---:|---:|---:|
| 新进程启动至地址栏可输入 / ms | 307.65 | 285.03 | -7.35% |
| 标签切换至两次 rAF 回调，中位数 / ms | 66.67 | 66.67 | -0.01% |
| 标签切换至两次 rAF 回调，P95 / ms | 101.54 | 100.88 | -0.65% |
| 四秒滚动 rAF 间隔 P95 / ms | 35.00 | 35.00 | +0.00% |
| 十标签空闲 CPU / 单核 % | 1.36 | 1.18 | -13.17% |
| 元素捕获服务至落盘 / ms | 18.16 | 15.85 | -12.76% |
| 整页捕获服务至落盘 / ms | 2228.49 | 2208.28 | -0.91% |

候选首轮启动为 **1131 ms**，基线也曾先有一次因前台丢失作废的启动。因此不从启动中位数约 7% 的差异宣称确定提速。CPU 仅为空闲单核百分比，不换算成电量或续航。

### 标签切换尾部波动调查

第一组各三轮：P95 为 68.85 → 108.91 ms，触发超过 10% 的调查。慢值主要位于闲置后第一遍切换。反向三轮：105.01 → 100.12 ms。合并全部六轮：101.54 → 100.88 ms。

没有删除任何较慢轮次，也没有换用更宽松的帧时间定义。此次未复现为跨顺序都稳定存在的版本回退，但波动来源尚未被精确定位；**不宣称标签切换已经明显变快**。首次调查数据及反向复查分别保存在本地 `qa-output/performance-010/comparison-initial.json` 和 `comparison-reverse.json`。

## 捕获与资源释放

以下为同一十标签长页面探针的整组物理内存中位数，包含归属该浏览器的 WebKit 服务，由系统 footprint 聚合，不累加 RSS。“刚结束”不是整个捕获过程的峰值。

| 阶段 | 0.9 / MiB | 0.10 / MiB |
|---|---:|---:|
| 十个长页面加载后 | 342.0 | 312.5 |
| 捕获前 | 348.6 | 343.2 |
| 元素捕获后 | 356.8 | 351.5 |
| 整页捕获刚结束 | 485.6 | 449.2 |
| 约 5 秒后 | 364.8 | 311.9 |
| 约 15 秒后 | 359.2 | 305.1 |
| 清空最新结果、关闭九个标签后 | 219.2 | 171.4 |

整页捕获约十五秒后的轮次范围：0.9 为 340.8–367.1 MiB，0.10 为 297.7–322.7 MiB。两版所有轮次均确认九个关闭的 WKWebView 释放，保留一个标签。上述下降不能推广到任意站点或长期无泄漏。

## 验收与剩余范围
